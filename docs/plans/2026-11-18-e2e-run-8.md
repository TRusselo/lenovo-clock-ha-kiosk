## Findings

1. **"Nothing was written" after a USB drop mid-write.** `why_failed` (`lck/mtk.py`) added "Nothing was written"
   to every USB drop. In restore it came after `boot`, `system` and part of `userdata` were written. **Fixed:** when
   mtkclient's output shows writing (`Write:` or `Wrote`), the reason is "the USB connection dropped, with the
   backup partly written. The next try writes it all again". Test:
   `test_a_usb_drop_while_writing_doesnt_say_nothing_was_written`.
2. **A power pull during the Magisk patch stopped setup.** The push of `boot.img` ended with "adb: error: failed to
   read copy response: EOF"; Root has the lost-clock recovery, but `_LOST` (`lck/clock.py`) didn't know this
   error, so it was a hard stop ("Stopped: adb failed: …"). The rerun patched again and went on. **Fixed:** the
   error counts as losing the clock: the step waits for it and starts again. Test:
   `test_an_adb_copy_cut_by_a_power_pull_counts_as_losing_the_clock`.
3. **"Nothing yet" came again after every reminder** in a long fastboot wait (21:51:43, 21:54:44, …): the reminder
   reset it. **Fixed:** once per wait. Test: `test_the_nothing_yet_hint_comes_once_per_wait`.

All three are in one commit, 154 tests passing, **not yet tried on the clock**.
