### Findings, most important first

1. **False "this computer account isn't allowed to use it" stop when a mode disappears.** `detect()` lists the USB
   devices, then checks `os.access` on the device file; when the clock leaves BROM or fastboot in between, the file
   is gone and that reads as "no permission". Hit 2 of 3 times the clock left a mode here (unlock step: BROM on the
   way to a normal start; root step: the person unplugging, as told). Fix: if access fails, look again; a device no
   longer listed has left the mode; stop only if the same device is still listed and refused after a second. And in
   a fastboot wait, BROM then nothing means "the clock started normally", which deserves its own message
   (once Android runs, the clock's USB does nothing).
2. **The Cast fallback can't work: `su -c` gets only the first command** (`lck/system.py` `_hide_cast`).
   `clock.shell()` passes its arguments to `adb shell`, which joins them for the clock's `sh`, so only `mkdir` runs
   as root and `cp`/`chmod`/`rm` run as the shell user ("cp: … Permission denied"). Quote the command as one
   argument (`shlex.quote`). It's the only chained `su -c` in the code. Tests mock adb, so they pass. Done by hand,
   correctly quoted, it works: Cast gone after a restart.
3. **Cast comes back even with the first clock's order** (disable, restart, uninstall for user 0, restart): three
   restarts (about 3 min) for nothing on this clock. The boot script is the only thing seen to work here. Consider
   going straight to it when root is there, or record which clock the other order worked on and why.
4. **The root step can't resume** after a stop between the boot flash and the Shell grant:
   - `RootStep.done()` is `has_root()`, so it patches and flashes again (another fastboot trip) although `su`
     answers (exit 13 or 1, not 127). Skip to the Magisk app when su exists.
   - The "Requires Additional Setup: tap OK" box assumes Magisk asks; on a resume it doesn't, so nothing restarts
     and the wait never ends. The person restarted the clock by hand. Check whether the setup is done, or say "if
     Magisk doesn't ask, press Enter".
   - After that restart Magisk isn't on screen, and the Shell box says "In Magisk, open …" with no way to open it
     (no app drawer yet). Open Magisk right before the box. (Claude opened it for the person.)
   These all came from an accidental Ctrl-C, but finding 1 sends people down the same path.
5. **Restart spinners start late, with wrong times:** "✓ Waiting for the clock to restart with Cast switched off
   (5s)" for a restart the log shows took 48 s; the screen sat still for ~40 s first.
6. **The "Clock mode:" line comes up late** (seen at the unlock step's fastboot page, and the restore's first BROM).
   One USB scan takes ~1 ms and the wait polls every 0.25 s, so the lag is elsewhere: worth timing against
   `udevadm monitor`.
7. **Bold, two rules from the person:**

     "fastboot"), not the ones passed on the way (BROM, 3 to 5 seconds).

     power-cycle box were still plain. One rule in `ui.py` would stop it being missed.

   it reads as the old instruction. Redraw and say "BROM mode again, to write".
9. **GitHub's limit:** also suggest turning a VPN on or off, or changing its location, to reach GitHub from a
