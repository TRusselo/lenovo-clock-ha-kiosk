Tool: `lck` at `b5837bd`. Workdir: `/mnt/nvme1/git2/work/lck-e2e2` (fresh; not the repo folder, whose

## Result

Stock to working kiosk in one pass, ending in "✓ All done. The clock is a Home Assistant kiosk." (2026-11-16
17:40), with one step that needed a hand: **Cast can't be removed without root on this clock.** The restore
took 13 min, setup about 45 min of tool time plus the person's turns. Home Assistant got the same device back
(same `lenovo_clock_*` ids, `media_player.lenovo_clock_player` idle, dashboard `clock-mini/home`, light sensor
reading): no new device.

### Findings, most important first

1. **Cast comes back after every restart** (`pm uninstall -k --user 0` answers Success, then it's reinstalled
   for user 0 at boot), so the degoogle step fails twice and stops setup. `pm disable` as root doesn't help
   (persistent app, started anyway). **What works:** a Magisk `post-fs-data.d` script that bind-mounts an empty
   folder over `/oem/app/com.google.android.apps.mediashell` (tested; ~257 MB free afterwards). Needs root, so
   reorder: Magisk before the degoogle step, or do the Cast part after Magisk. Fix NOTES.md's
   "`pm uninstall … works`", which was likely read before a restart.
2. **The power-cycle box after the flash is cleared at once** by the next step's address question, while the
   clock sits in fastboot off Wi-Fi. `keep()` it, or wait in the flash step until the clock leaves fastboot.
3. **The address question:** say where to find it on the clock (swipe up from the bottom, the gear, About
   device, IP address) and why the rest is over Wi-Fi (no USB adb under Android). The address changed since run
   1, so the tool must not rely on an old one.
4. **The fastboot box:** name the mode, and say holding passes BROM at 3 to 5 s and reaches fastboot at about
   8 ("about 10 seconds" is now in `FASTBOOT_PROMPT`; done in this run). The first try landed in BROM.
5. **Magisk Superuser instruction is wrong for v31.1:** there's no Shell entry to switch on. Steps: tap **+**,
   tick **Shell**, tap the back arrow (top left); Shell then shows with its switch on.
6. **"Found it. Let go of VOLUME UP"** prints even when no box was shown (clock already in fastboot):
   `fbmulti()`, `lck/flash.py:86`.
7. **A failed or skipped step shows ✓** after `--from` (Switch off Cast …). Needs its own mark.
8. **Failure screens show the wrong log tail:** the GitHub rate-limit stop showed the previous restore's
   mtkclient lines; the Cast stop showed a `pm list packages` dump. Log the error itself and name what failed
   (e.g. "Cast came back").
9. **GitHub's 60-an-hour limit stopped setup at the first step.** The message was clear, with a time. Fewer
   lookups (cache the Kiosk Satellite release) or an optional token would help on shared networks.
10. **The blank screen / four dots** after degoogle: say the screen stays blank (or shows Assistant's dots) until
    Kiosk Satellite is installed.
11. **Bold** "Unplug" and "Hold no buttons" in the power-cycle box, like VOLUME UP.
12. **Restore:** one overall bar (sizes are known) instead of a bar per partition; times (13 min against
    "about 40" and "about 45"); name the mtkclient download; drop "Alpine on slot B" from the warning.
13. **Intros are stale when steps are already done:** setup's intro still promises the 40-minute backup.
14. **Kiosk Satellite setup box:** mention its settings import.
15. **"✓ Waiting for the clock to restart (0s)"** after Magisk's extra setup: probably didn't wait for a restart.
16. **What's next** says "dashboard/README.md (in this folder …)", but "this folder" is the workdir, which has
    no `dashboard/`. Say "in the tool's folder", or give the link only.
17. **The flash guard** can't tell a restored stock clock (still unlocked) from a converted one. Fine, but the
    wording "may already be converted" was wrong here.

### Settled along the way

- **No USB adb under Android: observed.** With root: the cable that carried fastboot minutes earlier,
  `udc` state `not attached`, kernel `usb_state<DISCONNECTED>` every 5 s, while `sys.usb.config=adb`.
- Run 1's findings 2 and 3 (fastboot left after a stop; an unlock-step trip on an unlocked clock) didn't come
  up the same way: the unlock trip still happens, and the clock stayed in fastboot after the flash (finding 2).

## Setup of the run

- **Stock backup:** the clock's own backup from 2026-11-06, taken before the first unlock
  (`lenovo-smart-display-assist/smart-clock/backup/clock`, as converted to lck's format in
  `work/lck-e2e/backup/clock-stock`: same `full_user.bin.zst` SHA-256 `6b8c2394…`). Hardlinked into
  `lck-e2e2/backup/clock`. `verify_backup` → no problems.
- **Backup skipped, by seeding:** `BackupStep.done()` is true when `backup/<name>` verifies, so setup skips the
  backup. This is the one departure from what a real user does. Run 1 already showed the backup works.
- **Way back:** run 1's backup of the working kiosk, `lenovo-clock-ha-kiosk/backup/clock.zip`, left alone.
- **Kiosk Satellite settings:** the user has an export, and imports it through Kiosk Satellite itself.

## What this pass can't test

- `lck restore` never writes the bootloader or `seccfg`, so the clock stays unlocked. The unlock step's
  first-time path (`fastboot flashing unlock` + `at_auth_unlock.py`) isn't exercised; its "already unlocked"
  path and the flash step's `Type flash` guard are.
- The backup's `keep()` path across later screens (no new backup this run).

## Run 1 findings to recheck

   a stock clock is handled well.
2. Fastboot left after a stop, with no word about it.
3. A fastboot trip for the unlock step on an already-unlocked clock.
