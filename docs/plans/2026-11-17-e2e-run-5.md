## Findings

1. **No Wi-Fi step: a clock with no saved network is stranded after the flash.** Once Android runs, the clock's USB
   is host-only, so the tool only reaches it over Wi-Fi, and the only Wi-Fi it has is what the backup's user data
   holds. This clock had one (Observed, read-only: the backup's `/misc/wifi/WifiConfigStore.xml`, read with
   `debugfs`, has 1 `<Network>`) from its Google Home setup. A never-set-up or factory-reset clock has none, and
   would come up with no adb and no way to add a network. The docs list Wi-Fi as a requirement; nothing checks it.
   **The person's decision:** before anything is written, count `<Network>` in the backup's `WifiConfigStore.xml`
   (the userdata step already opens it with debugfs). If there is none, stop with both ways:
   - **Type the Wi-Fi name and password into the tool**, which adds the network to the copy of the user data in
     the same debugfs pass that switches on adb (the password stays in `work/`, like the backup's own Wi-Fi
     password does now). The format has to match Android Things 8.1's `WifiConfigStore.xml` exactly: copy the
     shape of an existing entry, **untested**.
   - **Or, for anyone who'd rather not type a password into a script:** set the clock up with the Google Home app,
     then run setup again. **Catch:** the backup was taken before that, so `BackupStep.done()` would reuse it with
     no Wi-Fi. The re-run must read the new user data from the clock (BROM, userdata only, into `work/`), never
     overwrite the stock backup. The clock is out of support (person), so Google Home won't update its firmware away
     from the backup. Google Home still sets it up (person), so both ways work.
   Launching Android Things' own Wi-Fi settings wouldn't help: with no network there's no adb to launch it with.
2. **Two "On the clock" boxes on screen at once in the root step** (start-normally box, then the Magisk box under
   it, the fastboot box above both). Redraw before each new box in a step, as restore's second BROM box does.
3. **Magisk's "tap OK" restart gave up at 90 s; the clock restarted just after** (uptime 36 s at the prompt; run 4
   took 1m 15s). Give up at 3 minutes, or keep watching the boot id at the prompt and carry on by itself.
4. **Magisk box wording (person):** **tap OK** in bold, and "Touch nothing else: the clock restarts by itself."
5. **Magisk opened in portrait both times this run.** Repeat the sideways note in the Shell box (or try rotating it).
6. **Make the addresses stand out (person):** colour/highlight the KS settings address in the box and the links in
   What's next. Those links also wrap badly ("(in the tool's folder, or" / the URL alone on the next line): put
   each URL on its own line, indented, highlighted.
7. **A seeded or older backup folder never gets a zip**, so "keep only the zip" (fix 10) can't happen: pack the
   folder when it checks out and has no zip.
8. **Connect box wording:** "Then: To find the clock's address, on the clock: swipe up…" reads as two sentences
   glued; "Then swipe up from the bottom, tap the gear (Settings), then About device: the address is under IP
   address."
