## Findings

1. **The Linux release's `debugfs` crashes on any PC with readline installed: setup can't get past "Build slot A".**
   The bundled `lck/e2fsprogs/debugfs` is static. At start, libss's `ss_get_readline` `dlopen`s the host's
   `libreadline`, and a static glibc binary segfaults doing that (exit 139, backtrace `main` → `ss_get_readline` →
   `__dlopen` → `_dl_init` → SIGSEGV). It happens even with `-R`, so every `debugfs` read comes back empty:
   both slots read as "not Android", the user data's build as "unknown". `e2fsck` (no libss) works. The system's
   `/usr/bin/debugfs` reads the same `system_a` fine: `ro.build.id=OIMJ.201212.001`.
   **Workaround, verified:** `SS_READLINE_PATH=none` makes libss skip the load (`env SS_READLINE_PATH=none
   ./lck/lck setup`).
   **Why CI missed it:** the release smoke test runs only `--version`, `selfcheck` and `--dry-run`; the live test
   uses the runner's apt e2fsprogs, not the bundled one, and the build container likely has no shared
   libreadline to load. Fix: set `SS_READLINE_PATH=none` in `userdata.ENV` (it is `None` now, so it inherits),
   and have the release smoke test run the bundled `debugfs -R "stat /"` on a small ext4 image on a runner
   with readline installed. Every Linux release up to v0.1.5 has the static build, so most Linux users were
   probably hit.
   **Fixed in v0.1.6:** `lck/e2fs.py` runs debugfs and e2fsck with `SS_READLINE_PATH=none` (tests
   `tests/test_e2fs_env.py`); `selfcheck` also runs the bundled `debugfs -R help`, and the Linux release job
   installs `libreadline8` first, so the crash would fail the build. Checked against v0.1.5's own debugfs and
   this run's images: `stat /` exit -11 before, 0 after; slot A `OIMJ.201212.001`, slot B `OIMK.211005.001`.
2. **A rerun asks for the Wi-Fi name and password again** after a stop. Minor: by design the password isn't
   saved; noted only because the person typed them 6 minutes earlier.
3. **The log fills with `dumpsys` output while the tool waits at the Superuser box.** 378 `adb shell dumpsys
   activity activities` calls in 26 minutes (one every 4 s, the watcher that closes Cast), each logging its whole
   output: about 22,700 of the log's lines, 1.7 MB by 19:11. Minor: it buries the rest of the log. Log the
   command and exit code, but not its output, as `log_output=False` does elsewhere.
